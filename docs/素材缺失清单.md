## 五、命名错误：双扩展名 `.mp4.mp4`（根因已定位，OSS 已清理）

曾经有 11 个卡片视频在 OSS 上的名字是 `xxx.mp4.mp4`，其中 5 个连干净的单扩展名版本都没有，按规范名引用必然 404：

| 文件（处理前）                  | 单扩展名版本（处理前） | 本地 `public/video/`          | 大小    |
| ------------------------------- | ---------------------- | ----------------------------- | ------- |
| `WEN_12_card_weizheng.mp4.mp4`  | 404                    | 有 `WEN_12_card_weizheng.mp4` | 29.2 MB |
| `WEN_13_card_war.mp4.mp4`       | 404                    | 有                            | 48.8 MB |
| `WEN_13_card_zhangqian.mp4.mp4` | 404                    | 有                            | 38.8 MB |
| `WEN_17_card_idiom.mp4.mp4`     | 404                    | 有                            | 38.7 MB |
| `WEN_17_card_myth.mp4.mp4`      | 404                    | 有                            | 36.8 MB |

另外 6 个（`WEN_18_card_fable`、`WEN_18_card_persist`、`WEN_22_card_book`、`WEN_22_card_zuozongtang`、`WEN_23_card_paper`、`WEN_23_card_printing`）两种名字都在，`.mp4.mp4` 是冗余副本。
11 个副本合计 **414 MB**，全是重复内容。

**根因**：不是上传脚本拼错了 key。上传是**在 OSS 控制台手工拖拽**做的，控制台把本地文件名原样收作 object 名；而待传目录 `card_video_upload_only/` 里的本地文件名**本身就是** `xxx.mp4.mp4`。已核对：这些双扩展名文件与 `public/video/xxx.mp4` 的 md5、大小、mtime 完全一致，是同一条视频被复制了一份、名字多出一层扩展。
最可能的来源是 Windows 的老坑——资源管理器默认隐藏扩展名时，把 `xxx` 重命名成 `xxx.mp4`，实际得到的是 `xxx.mp4.mp4`（**这一步是推断，未经复现**；能确认的是「多出来的扩展名在本地文件上就已存在，控制台只是忠实照搬」）。

**处理结果（本地改名 + 2026-10-26 控制台侧改完，均实测）**：

- 本地 11 个文件改回单层 `.mp4`，`card_video_upload_only/` 与 `public/video/` 的双扩展名文件数为 0，内容未动。
- OSS 直连（`classic-chinese.oss-cn-zhongwei`）与 CDN（`www.classicalab.cn`）两边复核：11 个 `xxx.mp4` **全部 200**，11 个 `xxx.mp4.mp4` **全部 404**，即已按规范名到位、冗余副本已清掉。
- 待传目录里 25 个卡片视频逐个 HEAD，**25/25 存在**，改名过程没有牵连其他文件。
- 同时重跑 `scripts/check-video-inventory.sh`：rule 视频仍是 128 存在 / 20 缺（13、16、17、33、34），culture_cards 与 text_basic_info 的 JSON 仍只有 01–04，**没有因为这次改名而变化**。

> 往后再往控制台拖文件，先打开「查看 → 文件扩展名」确认只有一层扩展名；`bash scripts/check-card-references.sh` 会同时做本地命名自检和线上引用核查。

## 六、顺带发现的上传隐患（本轮已修）

- **region 兜底值错误**：`scripts/upload-to-oss.js` 原本写死 `oss-cn-guangzhou`，而 `classic-chinese` 桶实测在 **`oss-cn-zhongwei`**（用 guangzhou 请求会被拒，OSS 在错误 XML 里回吐 `<Endpoint>oss-cn-zhongwei.aliyuncs.com</Endpoint>`；换 zhongwei 后同一对象直连 200）。已把兜底值和 `.env.example` 一起改成 zhongwei，并保留 `OSS_REGION` 环境变量覆盖。
- **上传前没有命名自检**：坏文件名（多一层扩展名、含空格、大小写混排如 `WEN_03_card_Linzexv.mp4`）传上去只会变成前端 404，本地却毫无提示。已给 `upload-to-oss.js` 加 `findSuspiciousNames()`，扫描每个待传目录后在上传（含 `--dry-run`）之前先打印告警。
- **引用与实存不一致没人管**：新增 `scripts/check-card-references.sh`，把每个已存在的 `/data/culture_cards/WEN_nn.json` 里引用的 `image_file`/`poster_file`/`background_image` 按前端同样的规则解析成 URL 逐个 HEAD，分成「404 真坏」和「名字可疑」两类；顺带对 `card_video_upload_only`、`public/video`、`public/images` 做本地命名自检。有问题退出码非 0，可直接放进流水线。它查的是**线上现在**的 JSON，所以直到本轮的清理发上去之前，它仍会报 `WEN_04_card_fish.png -> 404`；查**本地待发出**的 JSON 用的是第七节那个部署前脚本。
- 上一版里「双扩展名大概率出自脚本拼 key」的说法**已作废**，结论见第五节。

## 十一、word_list 里成不了 span 的 4 条词条（2026-10-29 补）

悬浮层已经做到 190/190 全命中（4 篇课文每个 `.annotated-word` 逐个派发 `mousemove` 验过），但**有注释点不出来**不等于**有注释能点**——`public/data/word_list/WEN_xx.json` 里有 9 条词条压根没变成 span。适配器这轮加了「剥括号注音」和「标点容错短语」两级兜底（见 `src/utils/adapterUtils.ts` 的三级匹配），其中 5 条已经补上：`鲦（tiáo）鱼`→「鲦鱼」、`槽枥(lì)`→「槽枥」、`外见(xiàn)`→「外见」、`乃丹书帛曰陈胜王`、`其必曰 “先天下之忧而忧，后天下之乐而乐” 乎`。

剩下这 4 条是**数据侧的事，代码故意不去够**：

| 课文   | 词条 `word` | 释义开头                                     | 为什么标不了                                                                                            | 该怎么改                                                                                                 |
| ------ | ----------- | -------------------------------------------- | ------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| WEN_02 | `食(sì)`    | 同「饲」，喂……                               | 剥掉注音只剩单字「食」，而正文里「食」出现 5 次、只有部分是 sì 读法。全标就是错标。                     | 词条拆成具体词形（如 `食马者` / `而食之`）并注明是哪一处，或干脆接受它只作为词表条目、不指望正文里能悬停 |
| WEN_02 | `马说`      | 选自《韩昌黎文集校注》卷一……                 | 释义是**出处说明**，`word` 是篇名；篇名只出现在 `.article-title`，正文 `original_text` 里没有这个词形。 | 出处类内容挪进 `text_basic_info`（或新增 `source_note` 字段），别混在 word_list 的字词注释里             |
| WEN_03 | `岳阳楼记`  | 选自《范仲淹全集》（凤凰出版社 2004 年版）…… | 同上                                                                                                    | 同上                                                                                                     |
| WEN_01 | `史记`      | （出处说明）                                 | 同上，而且「史记」这个字串在本篇 `original_text` 里根本不存在                                           | 同上                                                                                                     |

复现与复查（结果会随素材变，别照抄）：等价断言已经写进 `src/adapters/__tests__/wordListAdapter.test.ts` 的「每条词条要么已成 span，要么在已登记的『标不了』清单里」双向测试，CI 每次都会跑；本地随时复量：

```bash
npx vitest run src/adapters/__tests__/wordListAdapter.test.ts -t '标不了'
```

清单外的漏标会直接以用例失败的形式报出来（`「xxx」既没成 span、也不在"标不了"清单里`）；反过来，清单里的条目一旦被误标（比如哪天放开了单字音注，把 5 个「食」全标上）同样会红。

一句话给内容组：**字词的注音别写进 `word` 字段**（写进 `basic_meaning` 就行），**篇名出处不要放进 word_list**。这两条守住，前端就不需要任何特例。
