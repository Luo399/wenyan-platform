# 素材缺失清单

判定口径：前端所有课文数据与视频都**直连 OSS/CDN 读取**（`src/utils/asset.ts` 的 `getDataUrl` / `getAssetUrl`，生产基址 `https://www.classicalab.cn`），不经过后端接口。
所以下面每一条都是**实测**结果：对生产地址发 `HEAD` 请求，`404` 即视为缺失——浏览器里就是学生看到的那一个。

实测时间：2026-10-26（脚本：`curl -o /dev/null -s -w '%{http_code}' -I`）

---

## 一、rule 规则视频：缺 5 篇（20 个文件）

每篇需要 4 个文件：`{视频目录}/WEN_nn_rule_bg.mp4`、`_rule_1.mp4`、`_rule_2.mp4`、`_rule_3.mp4`（对应规则页背景 + 三个知识点讲解）。

37 篇 × 4 = 148 个文件，实测存在 **128** 个，缺 **20** 个。缺的不是零散文件，而是**整篇 4 个全缺**：

| 编号 | 按当前 `poemMap` 的篇名 | 缺失文件 |
|---|---|---|
| 13 | 送东阳马生序 | `WEN_13_rule_bg/1/2/3.mp4` |
| 16 | 答谢中书书 | `WEN_16_rule_bg/1/2/3.mp4` |
| 17 | 记承天寺夜游 | `WEN_17_rule_bg/1/2/3.mp4` |
| 33 | 北冥有鱼 | `WEN_33_rule_bg/1/2/3.mp4` |
| 34 | 咏雪 | `WEN_34_rule_bg/1/2/3.mp4` |

> 篇名一栏**不可信**：编号与篇目的对应关系目前只对 01–04 做过核实（见第四节），5–37 是代码里硬编码的推测表。等美术侧对照表给到、编号重排之后，这张表的「编号」列要跟着改，缺的**文件数量**不受影响。
>
> 已排除改名可能：这 5 篇没有任何 `_rule_0` / `_rule_intro` 之类的替代命名，也不在本地 `card_video_upload_only/` 里。

其余 32 篇（01–12、14、15、18–32、35–37）4 个文件齐全，`200 OK`。

## 二、第三关文化卡片：数据 JSON 缺 33 篇

| 项目 | 地址 | 实测 |
|---|---|---|
| 卡片数据 JSON | `/data/culture_cards/WEN_nn.json` | 仅 **01–04** 存在；05–37 全缺（33 个） |

后果比缺视频更麻烦：**卡片视频已经传上去了，但没有 JSON 去引用它们**。OSS 上现存 25 个 `{wenId}_card_*.mp4`，其中编号 6、7、8、9、10、11、12、13、17、18、22、23 的卡片视频（20 个文件）不属于任何一个已有 JSON——这批是**孤儿素材**，第三关打不开它们。

## 三、课文基础数据：JSON 缺 33 篇

| 项目 | 地址 | 实测 |
|---|---|---|
| 课文原文/标题/作者 | `/data/text_basic_info/WEN_nn.json` | 仅 **01–04** 存在（04 的正式标题是「庄子与惠子游于濠梁之上」）；05–37 全缺 |

本地 `public/data/` 各子目录同样只有 4–5 篇：`culture_cards` 4、`text_basic_info` 5、`level1_quiz` 5、`word_list` 6、`level2_dialog`/`level2_quiz`/`level3_quiz`/`level3_scenario_text`/`multi_role_reading` 各 1–5。
**所以这一项不是「做了没上传」，是数据本身还没产出**——5–37 这 32 篇目前只有规则视频，进第二、三关无题可答。

## 四、已引用但 404 的素材（学生现在就会撞到）

1. **`WEN_04_card_fish.png`（濠水之鱼）** —— `/data/culture_cards/WEN_04.json` 第 1 张卡片明确引用它，实测两个候选路径都 404：
   - `/video/WEN_04_card_fish.png` → 404
   - `/images/culture_cards/WEN_04/WEN_04_card_fish.png` → 404
   第三关 WEN_04 第一张卡片必然显示加载失败，**这是现网在跑的 bug**，优先级最高。
2. **`WEN_03_card_Linzexv.mp4`** —— 能 200，但拼写是 `Linzexv`（大小写混排 + 结尾 v），而本地/其他文件用的是 `linzexu`。目前能用，改数据时极易踩空。

## 五、命名错误：双扩展名 `.mp4.mp4`

OSS 上有 11 个卡片视频名字是 `xxx.mp4.mp4`。其中 **5 个没有干净的单扩展名版本**，等于按正常名字引用必然 404：

| 文件（OSS 现状） | 单扩展名版本 | 本地 `public/video/` |
|---|---|---|
| `WEN_12_card_weizheng.mp4.mp4` | 404 | 有 `WEN_12_card_weizheng.mp4` |
| `WEN_13_card_war.mp4.mp4` | 404 | 有 |
| `WEN_13_card_zhangqian.mp4.mp4` | 404 | 有 |
| `WEN_17_card_idiom.mp4.mp4` | 404 | 有 |
| `WEN_17_card_myth.mp4.mp4` | 404 | 有 |

另外 6 个（`WEN_18_card_fable`、`WEN_18_card_persist`、`WEN_22_card_book`、`WEN_22_card_zuozongtang`、`WEN_23_card_paper`、`WEN_23_card_printing`）两种名字都在，`.mp4.mp4` 是冗余副本，可清理。
**修法**：按单扩展名重传那 5 个（本地文件现成），再删掉 `.mp4.mp4` 副本。

## 六、顺带发现的上传脚本隐患

- `scripts/upload-to-oss.js` 的 region 兜底写的是 `oss-cn-guangzhou`，而 `classic-chinese` 桶实测在 **`oss-cn-zhongwei`**（匿名 ListObjects 被拒时 OSS 返回的 XML 里带出真实 region）。兜底值会在配置缺失时把上传打到错误 endpoint 上。
- 双扩展名大概率出自同一脚本拼 object key 时对已带 `.mp4` 的文件名又补了一次扩展。

## 八、代码侧已做的兜底（本清单同步落地）

缺失不该让学生撞黑屏。已按上面的实测结果加了一层「素材是否就绪」的判据与降级：

- `src/config/poemAssets.ts`：单张表记录「哪些编号的 rule 视频/卡片 JSON 已存在」，判据只认编号，等编号重排后仍可用。
- `src/utils/wenUtils.ts` `getAllPoems()`：条目新增 `ready` 字段。
- `src/components/NewMenu.vue`：未就绪的篇目置灰、标「制作中」、点不动（触屏连点/键盘 Enter 都拦）。
- `src/views/RuleVideoView.vue`：直接输 URL 进来也不渲染播放器，改为「本篇素材正在制作中，敬请期待」占位，并隐藏「继续」，不让学生跳进空白的第二关。
