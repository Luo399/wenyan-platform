# Figma 扫描资产使用审计（2026-10-29）

审计对象：Figma 插件通过 `Export Assets` / `文字资源_*` / `样式_*` 扫描并上传到生产 OSS 的产物。
问题来源：甲方问「看 figma 扫描出来的东西是否全部用上」。

> 结论口径分两层：**运行时引用**（前端代码/数据 JSON 是否真的请求它）与**设计底稿引用**
> （内容/设计同学是否拿它当出图依据）。第二层没有代码证据，本审计只回答第一层，
> 并把第二层的已知用途单独标注。

## 一、结论先说

1. **没有全部用上，运行时使用率接近于零。**
   插件扫描产物共 **6,075 项**：`images/screens/**` 6,049 项 + `data/texts/**` 26 项；
   `styles/**` 目录为空。
2. **`images/screens/**`运行时引用 0 项。** 全仓只有`DialogueCard.vue`会通过`resolveScreenAsset()`探测`images/screens/{wenId}/dialogue/{icon_dialog}`，
但现有 25 个 `icon_dialog` 字段**全部为空字符串**；quiz / explanation / summary /
   cultural_card / video 五类切片没有任何组件消费。
3. **`data/texts/**`前端零消费。**`src/`内没有读取`data/texts` 的代码；它更像内容组
   整理页面 JSON 时使用的文字底稿。
4. **真正在用的 Figma 通用图只有 3 张**：
   `images/login_bg.png`、`images/general/article_list_bg.png`、
   `images/general/article_list_title.png`。
   同目录的 `images/general/card_scroll.png` 只有注释提到，代码未引用。
5. 页面里大量出现的音频、卡片视频**不是** Figma 切片：它们分别来自 `audio/**` 与
   `video/**`，其中文化卡片通过 `image_file: *.mp4` 走 `/video/`，与 `images/screens` 无关。

## 三、代码侧证据（为什么说没接上）

### 3.1 图片切片

- 唯一消费 screens 的组件是 `src/components/DialogueCard.vue`：
  `resolveScreenAsset(wenId, 'dialogue', iconDialog)` → 命中才用，失败回退 `images/{name}`。
- 数据侧 `icon_dialog`：`public/data/**` 共 25 个字段，**非空 0 个**。
- 数据侧 `illustration`：共 8 个字段，**非空 0 个**，且没有组件读取该字段。
- quiz / explanation / summary / cultural_card / video 五类目录在 `src/` 中没有任何路径引用。
- 通用图：`grep getAssetUrl('images', ...)` 的静态引用只有
  `login_bg.png`（4 个登录页）、`general/article_list_bg.png`、`general/article_list_title.png`。
  `images/general/card_scroll.png` 未被引用。

### 3.2 文字资源

- `src/`、`backend/src/` 内没有读取 `data/texts/**` 的业务代码；
  后端仅在资产管理端点里按目录列清单/删除，不参与页面渲染。
- 这些文件是插件按 TEXT 节点生成的 `文字资源_{篇名}.json`，实际用途是内容组整理
  `pages_*` / `level*_quiz` 数据时的文字底稿；属于设计/内容流程，不是运行时依赖。

### 3.3 样式资源

- 生产桶 `styles/` 为空；后端注释明确 `/api/assets/styles/:name` 已下线，
  前端无调用方，插件仍保留 `样式_*` 导出能力但当前没有产物。

## 四、判断

- 如果「用上」指**学生端能看到的页面元素**：Figma 切片基本没用上，只有 3 张通用背景/标题图。
- 如果「用上」指**内容生产时的设计依据**：`images/screens` 与 `data/texts` 有价值，
  但这一步发生在 Figma/内容组侧，仓库无法证明每一张都被看过。
- 当前的直接后果是：生产桶里 6,000+ 个切片既不被请求，也没有归档标记，
  后续做资源清理或迁移时分不清「漏挂」与「纯设计稿」。

## 五、建议（按优先级）

1. **先标注，不急着删。** 让设计/内容组确认哪些切片是「待挂载」、哪些是「纯设计底稿」；
   纯底稿迁到 `design/**` 前缀或只留 Figma，不再随插件增量上传到生产桶。
2. **如果要挂对话头像**：给 `pages_level2_dialog_quiz/*.json` 的 `icon_dialog` 填
   `images/screens/{wenId}/dialogue/` 下的文件名，`DialogueCard` 现有逻辑即可生效；
   填完用 HEAD 探一遍 200。
3. **如果要挂题目/解析/总结插图**：现有页面 schema 没有对应字段，需要先定字段
   （例如 `quiz.image_file`、`dialogue.illustration`）和组件渲染位置，不能只上传文件。
4. **把 `data/texts` 明确为内容底稿**：不要放进运行时桶的增量同步清单；
   或在内容构建脚本里消费它，避免「上传了但没人读」。
5. **加一条资产引用审计**：以本审计的统计口径（数据字段 → 实际 URL → HEAD 200）
   做成发布前检查；同时反向检查「OSS 有、数据零引用」的目录，按季度清理。

## 六、复算方法

```bash
# 1) 生产桶全量清单（对象路径 + 分类计数）
curl -s https://api.classicalab.cn/api/assets/oss-list -o oss-list.json
# 2) 上传清单（插件 version.json 口径）
curl -s https://api.classicalab.cn/api/assets/version -o version.json
# 3) 数据字段引用（icon_dialog / illustration / image_file 等）
bash scripts/check-data-references.sh   # 或按 docs/素材对应核查.md 的脚本口径
# 4) 代码引用
rg "images/screens|data/texts|getAssetUrl\('images'" src backend/src
```

统计脚本用 `scripts/check-asset-correspondence.sh` 与
`scripts/check-data-references.sh` 的现有口径；本审计只补充「上传产物 → 运行时引用」这一层。
